# نظام المصطفى لإدارة المصانع 🏭

نظام متكامل لإدارة المصانع يشمل المخازن، المبيعات، المشتريات، التصنيع، والحسابات.

## المتطلبات الأساسية

- Node.js (v18+)
- PostgreSQL (v14+)
- npm أو yarn

## خطوات التثبيت

1.  **استنساخ المشروع:**
    ```bash
    git clone <repository-url>
    cd ELMostafa
    ```

2.  **تثبيت الاعتماديات:**
    ```bash
    # تثبيت اعتماديات الواجهة الخلفية
    cd backend
    npm install

    # تثبيت اعتماديات الواجهة الأمامية
    cd ../frontend
    npm install
    ```

3.  **إعداد قاعدة البيانات:**
    - قم بإنشاء قاعدة بيانات جديدة باسم `elmostafa_db`.
    - يمكنك استخدام السكربت المرفق (إذا كنت تستخدم Linux):
      ```bash
      ./install_db.sh
      ```

4.  **تشغيل النظام:**
    - يمكنك تشغيل النظام بالكامل (Backend + Frontend) باستخدام السكربت:
      ```bash
      ./start.sh
      ```
    - أو تشغيل كل جزء منفصل:
      - **Backend:** `cd backend && npm run start:dev` (Port 3001)
      - **Frontend:** `cd frontend && npm run dev` (Port 3000)

## الميزات الرئيسية

- **المخازن:** إدارة المنتجات، الخامات، وحركات المخزن.
- **المبيعات:** إدارة العملاء وأوامر البيع.
- **المشتريات:** إدارة الموردين وأوامر الشراء.
- **التصنيع:**
    - إدارة الماكينات والقوالب (إسطمبات).
    - تسجيل الإنتاج اليومي.
    - معادلات التصنيع (BOM).
    - أوامر التجميع.
- **الحسابات:**
    - شجرة الحسابات.
    - قيود اليومية.
    - ميزان المراجعة.

## النسخ الاحتياطي

يوجد سكربت للنسخ الاحتياطي التلقائي لقاعدة البيانات:
```bash
./backup.sh
```
سيقوم بإنشاء مجلد `backups` وحفظ نسخة يومية.

## 📁 دليل ملفات النظام (File-by-File Guide)

هذا الدليل يشرح وظيفة كل ملف موجود في المجلد الرئيسي للنظام:

### 🛠️ سكربتات التشغيل (Scripts)

1. **`start.sh`**
   - **ما هو؟** سكربت لتشغيل النظام بالكامل بضغطة واحدة على أنظمة لينكس.
   - **لماذا؟** لتسهيل تشغيل السيرفر والواجهة الأمامية معاً بدلاً من فتح نافذتين.
   - **استخدامه:** تشغيل النسخة التطويرية (Development) للمبرمجين أو التجربة السريعة.
   - **كيف يعمل؟** يغلق أي عمليات قديمة، يبدأ السيرفر (Backend)، ينتظر حتى يجهز، ثم يبدأ الواجهة (Frontend).

2. **`start-prod.sh`**
   - **ما هو؟** سكربت تشغيل النظام في وضع "الإنتاج" (Production) على لينكس.
   - **لماذا؟** ليكون النظام أسرع وأكثر استقراراً عند العمل الفعلي في المصنع.
   - **استخدامه:** التشغيل النهائي للسيرفر ليخدم جميع الأجهزة.
   - **كيف يعمل؟** يقوم ببناء (Build) المشروع ثم يستخدم برنامج PM2 لإدارته في الخلفية.

3. **`backup.sh`**
   - **ما هو؟** سكربت لعمل نسخة احتياطية من البيانات.
   - **لماذا؟** لحماية بيانات المصنع من الضياع في حالة حدوث مشكلة في الجهاز.
   - **استخدامه:** يفضل تشغيله يومياً.
   - **كيف يعمل؟** يأخذ نسخة من قاعدة البيانات ويحفظها في مجلد `backups` مع التاريخ.

4. **`restore.sh`**
   - **ما هو؟** سكربت لاسترجاع البيانات من نسخة احتياطية.
   - **لماذا؟** لإعادة النظام كما كان في حالة حدوث خطأ أو نقل النظام لجهاز جديد.
   - **استخدامه:** عند الحاجة لاستعادة بيانات قديمة.
   - **كيف يعمل؟** يمسح قاعدة البيانات الحالية ويستبدلها بالبيانات الموجودة في ملف النسخة الاحتياطية.

5. **`install_db.sh`**
   - **ما هو؟** سكربت لتثبيت قاعدة بيانات PostgreSQL على لينكس.
   - **لماذا؟** لتجهيز الجهاز الجديد ليعمل عليه النظام.
   - **استخدامه:** مرة واحدة فقط عند أول تثبيت للنظام.
   - **كيف يعمل؟** يقوم بتنزيل PostgreSQL وإنشاء قاعدة البيانات والمستخدم اللازم.

### 🪟 ملفات ويندوز (Windows Files)

- **`setup-windows.ps1`**: سكربت إعداد النظام لأول مرة على ويندوز (تثبيت المكتبات وإنشاء قاعدة البيانات).
- **`start-windows.ps1`**: سكربت تشغيل النظام (النسخة التطويرية) على ويندوز.
- **`start-prod-windows.ps1`**: سكربت تشغيل النظام (النسخة النهائية المستقرة) على ويندوز باستخدام PM2.
- **`WINDOWS-README.md`**: دليل مخصص لمستخدمي ويندوز يشرح كيفية التثبيت بالتفصيل.

### ⚙️ ملفات الإعدادات (Configuration)

- **`ecosystem.config.js`**: ملف إعدادات برنامج PM2 المسؤول عن إبقاء النظام يعمل في الخلفية وإعادة تشغيله تلقائياً إذا توقف.
- **`package.json`**: ملف يحتوي على معلومات المشروع والمكتبات الأساسية المستخدمة (في المجلد الرئيسي يعمل كحاوية).
- **`DEPLOYMENT-GUIDE.md`**: دليل يشرح كيفية نقل النظام لسيرفر آخر وتشغيله عبر الشبكة الداخلية للمصنع.
- **`README.md`**: هذا الملف الذي تقرأه الآن، وهو الواجهة الرئيسية للمشروع.
- **`startup.log`**: ملف يسجل ما يحدث عند تشغيل النظام للمساعدة في حل المشكلات إذا لم يفتح البرنامج.
